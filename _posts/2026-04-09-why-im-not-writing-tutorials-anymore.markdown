Hello again! It's been quite a while.

If you have followed this site for any length of time, then you probably know that I originally intended for JLSunday.com to be a place for tutorials, tool recommendations, project breakdowns, and the occasional rambling post on whatever I happened to be learning at the time.

And honestly, I still like that idea.

I still like tutorials. I still like detailed write-ups. I still like explaining why I built something a certain way, or sharing tools that made my life easier. That part has not changed.

What *has* changed is the world around programming.

## Intro

Over the last few years, AI assistants and coding agents have gotten good enough that the value of a traditional tutorial is just not what it used to be.

If you need:

- a quick explanation of a library
- an example config file
- a starter component
- help wiring up a Docker container
- a basic walkthrough of some framework feature

...you can usually get a decent first pass from an AI tool in seconds.

Now, to be clear, I am not saying those answers are always correct. They definitely are not. Sometimes they are incomplete, sometimes they are misleading, and sometimes they are just flat-out wrong. But they are fast, interactive, and usually good enough to get someone moving.

That changes things.

If I spend a bunch of time writing a long tutorial on a framework setup, there is a pretty good chance that by the time someone reads it:

- the framework version has changed
- the package list has shifted
- some CLI command is different
- the screenshots are outdated
- and an AI assistant can already recreate most of the basic steps on demand anyway

So lately I have been asking myself a different question.

Not, "Should I still write technical content?"

But rather, "What kind of technical writing still feels worth writing?"

## What Still Seems Worth Writing

For me, the answer is less about step-by-step instruction and more about judgment.

Because if I am being honest, the hard part of modern development is not always getting *an* answer anymore. The hard part is deciding whether the answer you got is actually any good.

That seems especially true now that AI agents are being used to:

- suggest packages
- scaffold projects
- make code changes
- explain code they did not write
- recommend architecture decisions
- and generally sound much more confident than they deserve to sound

That is where I think human-written posts still matter a lot.

I am much more interested these days in questions like:

- When should you trust an agent's recommendation?
- When should you add a new dependency versus reuse what you already have?
- How do you evaluate whether a package is worth the risk?
- What should code review look like when part of the code came from an agent?
- What parts of programming are becoming easier, and what parts are quietly becoming more dangerous?

Those questions feel much more alive to me right now than "Here is how to click through a setup wizard" or "Here is how to create a component in framework X."

## Why This Shift Feels Personal

Part of this is also just where my own head has been lately.

A lot of what I have been thinking about recently has less to do with tutorials and more to do with tooling, workflow, package discovery, trust, security checks, and the awkward but fascinating reality of programming alongside AI agents.

I keep coming back to problems like:

- how an agent should decide which package is a good fit for a project objective
- how to compare similar packages in a way that is actually useful
- how to avoid blindly introducing risky dependencies
- how to organize public and private workspaces while building tools in public
- how to design tools that make agents genuinely more helpful instead of just more active

That is the stuff I find myself wanting to write about.

Not because tutorials are bad, but because these questions feel more durable and more honest for where software development is right now.

## So, Am I Done Writing Tutorials?

Not necessarily.

I would not be surprised if I still write the occasional tutorial or walkthrough when I have something specific that seems truly worth documenting in depth. There are still plenty of situations where a good tutorial is useful, especially for fundamentals or for topics where context matters more than raw instructions.

But I do not want the site as a whole to be centered around tutorial-first content anymore.

There is already a massive amount of how-to content out there, and now AI tools can generate even more of it on demand. I do not think the best use of this site is to compete with an endless stream of interchangeable setup guides.

What feels more worthwhile to me is writing the kind of post that helps someone think through a problem more clearly.

That means more posts about:

- tradeoffs
- tooling choices
- package trust
- workflow design
- product decisions
- agent-assisted development
- security and review concerns
- and whatever other weird corners of modern programming I end up stuck in

So, yes, there will probably be fewer tutorials here than I originally planned.

But ideally, there will also be more signal.

## What I Expect To Write About Next

At the moment, I expect a lot of future posts to revolve around:

- AI-agent skills and tools for developers
- safer package and dependency selection
- the difference between useful automation and noisy automation
- build-vs-buy decisions
- workspace and repository organization
- practical thoughts on programming when agents are part of the workflow

Some of those posts will probably be half musing, half technical write-up. Some may turn into project notes. Some may become proper deep-dives. I am fine with that. I would rather let the writing follow the actual work than force it into the shape I imagined for this site a few years ago.

## Final Words

So, in short: this site is still about programming, but the writing is shifting.

Less tutorial-first.

More musings, insights, experiments, and practical thinking about development in the age of AI agents.

If you have been around since the earlier version of the site, thanks for sticking with me. And if any of these topics sound interesting to you, I think the next phase of this site will be a lot more fun to write than the old one would have been.
